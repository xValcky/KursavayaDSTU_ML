# Описание графиков вкладки «Аналитика ML»

> Вкладка видна в режиме «Про». Цифры взяты из текущей версии программы: 286 моделей,
> 14 групп, 6000 обучающих анкет. После переобучения они немного изменятся.

---

### 1. Карта групп
**Научным языком:**
Каждый телефон — точка в 18-мерном пространстве признаков:
- признаки стандартизованы, к скошенным применён логарифм, выбросы обрезаны по 5-му и 95-му
  перцентилям, каждый признак умножен на свой вес;
- чтобы нарисовать это на плоскости, применён метод главных компонент (PCA): оси «Главная компонента 1»
  и «Главная компонента 2» — две направляющие с наибольшей дисперсией данных.

Цвет точки — кластер. Кластеры получены методом k-means++ отдельно внутри каждого ценового класса
(«шпиля»), плюс отдельная группа «броневиков» по правилу «вес ≥ 300 г». Форма маркера — класс:
○ бюджетный, □ средний, △ флагман. Крестик — центроид кластера. Эллипс — область разброса группы
(эллипс доверия по ковариации). В таблице под графиком — средние характеристики каждой группы.

**Простым языком:**
Это карта рынка смартфонов, на которой телефоны с похожим «характером» лежат рядом. Как карта города,
где районы раскрашены разными цветами: все камерофоны в одном районе, автономные — в другом.
Крестик — «центр района», эллипс — его границы. Если ваш телефон-мечта лежит далеко от остальных,
значит, у него необычное сочетание характеристик.

### 2. Профили групп
**Научным языком:**
Слева — лепестковая диаграмма (radar chart) для 6 крупнейших кластеров. Каждый луч — признак:
цена, мощность, камера, работа активно, ожидание, экран, лёгкость, зарядка, плавность. Значение
на луче — средний перцентиль признака внутри кластера (0 — хуже всех в базе, 1 — лучше всех).
Для лёгкости шкала инвертирована, для частоты экрана используется «эффективная частота»
(выше 120 Гц — с коэффициентом 0,2). Справа — диаграмма размаха (boxplot) цен внутри каждого
кластера: медиана, межквартильный размах, усы, выбросы.

**Простым языком:**
Слева — «паутинка» для каждой группы. Чем дальше линия от центра по направлению «Камера», тем лучше
у этой группы камеры по сравнению со всем рынком. Как карточка персонажа в игре с полосками силы,
ловкости и выносливости: сразу видно, кто в чём силён. Справа — сколько стоят телефоны каждой группы:
жирная черта — типичная цена, коробка — где лежит половина цен, точки — исключения.

### 3. Цена и мощность
**Научным языком:**
Диаграмма рассеяния: по горизонтали цена (логарифмическая шкала, тыс. ₽), по вертикали
производительность AnTuTu (тыс. баллов). Цвет точки — кластер, размер — ёмкость батареи.
Пунктиром показан тренд: регрессия AnTuTu по логарифму цены (`np.polyfit`) по всей базе.
Подписаны 4 модели с наибольшим положительным остатком: у них производительность сильнее всего
превышает ожидаемую при их цене.

**Простым языком:**
Сколько «мощности» вы получаете за свои деньги. Пунктир — «средняя цена мощности на рынке».
Телефоны выше пунктира — выгодные: мощнее, чем обычно за такие деньги. Подписаны четыре
самых выгодных. Как в магазине сравнивать цену за килограмм: выше линии — дешевле за килограмм.

### 4. Классы
**Научным языком:**
Слева — две столбчатые диаграммы:
- распределение телефонов по классам 0/1/2 (114 / 92 / 80);
- распределение синтетических обучающих анкет по классам. Это проверка баланса классов
  для классификатора.

Класс телефона — разметка по взвешенной сумме перцентилей: цена 35%, AnTuTu 25%, камера 10%,
ОЗУ 10%, эффективная частота 10%, зарядка 5%, год 5%. Пороги — квантили 0,40 и 0,72.
Справа — таблица сопряжённости «кластер × класс» в виде тепловой карты: сколько телефонов каждого
класса в каждой группе.

**Простым языком:**
Программа делит все телефоны на три «весовые категории»: бюджетные, средние, флагманы. Левый график
показывает, сколько телефонов в каждой категории и сколько учебных примеров видела нейросеть.
Если бы одной категории было намного меньше, нейросеть плохо бы её узнавала, как ученик, решивший
мало задач одного типа. Правая картинка — какие группы из каких категорий состоят.

### 5. Выбор k и стабильность
**Научным языком:**
- Таблица по каждому шпилю: число моделей, выбранное k, средний коэффициент силуэта, стабильность
  и размеры групп. Стабильность — средний Adjusted Rand Index между разбиениями KMeans
  с 10 разными `random_state`.
- График «Метод локтя» — зависимость суммы квадратов расстояний до центров (inertia) от k.
- График «Силуэт по k». k выбирается в диапазоне 3–5: наибольшее k, у которого силуэт не хуже
  лучшего более чем на 0,04, при условии, что самая маленькая группа ≥ 8 моделей.
- Силуэтный график: для каждого телефона коэффициент силуэта, отсортированный внутри кластера;
  пунктир — среднее.

Текущие значения:
| Шпиль | k | Силуэт | ARI |
|---|---|---|---|
| Бюджет | 5 | 0,337 | 0,987 |
| Средний | 5 | 0,253 | 0,992 |
| Флагманы | 3 | 0,302 | 0,984 |

**Простым языком:**
На сколько групп делить телефоны? Если групп мало, всё смешано; если много — в группе по 1–2 телефона.
«Локоть» — место, где добавлять группы уже почти бесполезно, как сгиб руки на графике. Силуэт
показывает, насколько каждый телефон «свой» в своей группе: близко к 1 — точно на месте, около 0 —
на границе, меньше 0 — скорее из соседней группы. ARI около 0,99 значит, что при повторном запуске
группы получаются почти такими же. Результат не случайный.

### 6. Дендрограмма
**Научным языком:**
Иерархическая агломеративная кластеризация (SciPy `linkage`) с полной связью (complete linkage)
и евклидовой метрикой в том же взвешенном пространстве признаков. Листья — модели телефонов.
Высота горизонтальной перемычки — расстояние, на котором объединяются два кластера: при complete
linkage это максимальное расстояние между их элементами. Разрезав дерево горизонталью на любой высоте,
получаем разбиение на соответствующее число групп. Метод используется как контроль для KMeans:
его не нужно заранее задавать k.

**Простым языком:**
Генеалогическое дерево телефонов. Внизу каждый телефон сам по себе, выше они попарно «женятся»
с самыми похожими, потом объединяются семьи, потом кланы. Чем выше перемычка, тем меньше похожи
объединяемые группы. Проведите воображаемую горизонтальную линию: сколько веток она пересекла,
на столько групп и делится рынок.

### 7. Признаки и веса
**Научным языком:**
Слева — матрица корреляций Пирсона между 18 стандартизованными признаками; подписаны значения
|r| ≥ 0,5. В центре — итоговые веса признаков для кластеризации (1 — средний вес). Вес считается
в три шага:
1. экспертный вес;
2. делитель по взаимной информации (mutual information) с меткой класса: признаки, которые уже
   определяют класс, — меньше вес;
3. штраф за избыточность: сумма превышения |r| над 0,6 с другими признаками.

Справа — таблицы:
- веса и MI;
- сравнение вариантов кластеризации: без весов, с весами, по шпилям;
- сравнение алгоритмов: KMeans, агломеративная (complete и ward), DBSCAN — по силуэту и индексу
  Дэвиса–Боулдина.

**Простым языком:**
Левая картинка показывает, какие характеристики ходят парой: дорогие телефоны почти всегда
и мощные, поэтому «цена» и «AnTuTu» сильно связаны. Если считать их обе в полную силу, они задавят
остальное, как два громких человека в разговоре. Поэтому программа выдаёт каждой характеристике
«громкость» — это график весов: синие столбцы важнее среднего, серые — тише.

### 8. Нейросеть
**Научным языком:**
Слева — кривая обучения многослойного перцептрона (MLPClassifier):
- архитектура (64, 32), ReLU, оптимизатор Adam, L2-регуляризация α = 0,001, ранняя остановка;
- функция потерь log-loss по эпохам на обучающей выборке и точность на валидационной (вторая ось).

Вход — 49 признаков: 21 из анкеты и по 2 на каждый из 14 кластеров (лучшая полезность в кластере
и доля моделей в бюджете). Выход — вероятности классов 0/1/2. Справа — матрица ошибок
на тестовой выборке (15% данных): количество и доля по строке. Метрики теста: accuracy 0,849,
F1-macro 0,845, ROC AUC (one-vs-rest) 0,957.

**Простым языком:**
Как нейросеть училась: левая линия «ошибки» падает — сеть учится, вторая линия «точности» растёт.
Обучение останавливается само, когда точность перестаёт расти: зубрёжка без понимания вредна.
Справа — «работа над ошибками»: по диагонали — сколько раз сеть угадала класс, вне диагонали —
с чем путала. Чаще всего путает соседние классы («средний» и «флагман»), а «бюджетный» с «флагманом» —
почти никогда.

### 9. Сравнение моделей
**Научным языком:**
Абляционный эксперимент. Семь классификаторов обучаются на одних и тех же анкетах в двух вариантах:
только признаки анкеты (21) и анкета плюс признаки кластеров (49). Модели:
- логистическая регрессия, дерево решений, KNN, MLP;
- ансамбль Majority Vote, Bagging деревьев, AdaBoost.

Метрика — accuracy при 5-кратной кросс-валидации. Цифра у столбцов — прирост от кластеризации.
Сейчас прирост у всех семи моделей: от +0,9 п.п. (дерево) до +16,8 п.п. (KNN: 0,652 → 0,820);
у нейросети — 0,802 → 0,841. В таблице также стандартное отклонение по фолдам и F1-macro.

**Простым языком:**
Помогает ли кластеризация угадывать, какой телефон нужен человеку? Проверка простая: семь разных
«учеников» решают одну задачу с подсказкой («вот какие группы телефонов бывают») и без неё. Синий
столбец — с подсказкой, серый — без. У всех синий длиннее, значит, группировка действительно полезна,
а не сделана для красоты.

### 10. Ансамбли и ROC
**Научным языком:**
- **ROC-кривые** пяти моделей. Микроусреднение по трём классам, вероятности получены 3-кратной
  кросс-валидацией (`cross_val_predict`). По осям — доля ложных срабатываний (FPR) и доля верных
  (TPR) при всех порогах. В легенде — площадь под кривой (AUC): логистическая регрессия 0,968,
  Majority Vote 0,967, MLP 0,961, KNN 0,950, дерево 0,944.
- **Области решений** четырёх моделей на 2D-проекции анкет (PCA): цвет фона — предсказанный класс,
  точки — анкеты.
- **Ошибка ансамбля** из 11 независимых классификаторов как функция ошибки одного. Биномиальная
  модель: ансамбль ошибается, если ошиблись ≥ 6 из 11. При ошибке одного < 0,5 голосование её уменьшает.

**Простым языком:**
- ROC-кривая показывает, насколько хорошо модель отличает «свой» класс от чужих. Чем сильнее кривая
  прижата к левому верхнему углу, тем лучше; диагональ — угадывание монеткой. AUC 0,96 — это очень хорошо.
- Цветные карты справа — как разные модели «делят территорию»: дерево режет прямыми ступеньками,
  KNN — рваной границей, ансамбль — плавно.
- Нижний график — почему совет 11 экспертов надёжнее одного: если каждый прав хотя бы чуть чаще, чем
  ошибается, большинство ошибается намного реже. Это работает, только пока каждый лучше монетки.

### 11. Регрессия цены
**Научным языком:**
Задача — предсказать «справедливую» цену телефона по характеристикам. Целевая переменная — ln(цены),
признаки — характеристики и бренд (one-hot). Сравниваются 13 методов при кросс-валидации:
- парная и множественная линейная регрессия;
- нелинейная степенная модель через `curve_fit`;
- KNN и SVR — с масштабированием и без;
- дерево решений, случайный лес, бэггинг, градиентный бустинг;
- персептрон из одного нейрона и многослойный персептрон.

Гиперпараметры подбираются через GridSearchCV. Лучший сейчас — множественная регрессия:
MAE ≈ 6 185 ₽, или 15,8%, корреляция 0,933. Её out-of-fold прогноз и есть «справедливая цена».

Подвкладки:
- **«Сравнение методов»** — 4 графика: «факт против прогноза», остатки, парная регрессия
  по самому связанному признаку (AnTuTu), столбцы MAE % по методам.
- **«Дерево решений»** — дерево глубины 3 для ln(цены).
- **«Подозрительные цены»** — 24 модели с наибольшим расхождением цены и прогноза.

**Простым языком:**
Программа учится оценивать телефон «на глаз», как опытный продавец: «за такую начинку обычно
просят столько-то». Лучший «оценщик» ошибается в среднем на 16%. Если реальная цена сильно ниже
оценки — это выгодно, если выше — переплата за бренд. Точки на линии «факт = прогноз» — телефоны
с «честной» ценой. Дерево показывает логику оценки как набор вопросов: «AnTuTu больше 1 млн? Это Apple?».
«Подозрительные цены» — список на проверку: либо реальная акция, либо ошибка в данных.

### 12. Прогноз цен
**Научным языком:**
Из истории цен (Telegram-каналы и августовская оценка) строится дневной индекс цен по каждому шпилю
и по рынку: цена модели, делённая на её медианную цену. Прогноз — задача обучения с учителем
на скользящем окне лагов, горизонты 1 и 7 дней (многовыходная регрессия для 7 шагов). Сравниваются:
- наивный прогноз («завтра как сегодня») и скользящее среднее;
- линейная регрессия, случайный лес, градиентный бустинг, MLP.

Метрика — MAE в процентных пунктах индекса на отложенном хвосте ряда. Пунктиром на графике —
прогноз на 7 дней лучшей моделью. Из прогноза формируется совет «покупать сейчас / подождать»
в окне характеристик телефона.

**Простым языком:**
Как прогноз погоды, только для цен. Линия на уровне 1 — «обычная» цена, выше — сейчас дороже обычного,
ниже — дешевле. Пунктир — куда, по мнению программы, цены сдвинутся за неделю. Наивный прогноз
«завтра как сегодня» — честная планка: если умная модель его не обгоняет, ей нельзя верить.

### 13. Эталон Wine
**Научным языком:**
Проверка корректности реализации на классическом наборе UCI Wine: 178 образцов, 13 химических
признаков, 3 сорта. Те же 7 классификаторов оцениваются 10-кратной кросс-валидацией:
| Метод | Точность |
|---|---|
| Логистическая регрессия | 0,983 |
| Majority Vote | 0,972 |
| Bagging | 0,972 |
| KNN | 0,967 |
| AdaBoost | 0,961 |
| Дерево | 0,944 |
| MLP | 0,933 |

Дополнительно KMeans (k = 3, без учителя) сравнивается с настоящими сортами: ARI 0,897, NMI 0,876.
Для сравнения приведены опубликованные результаты (leave-one-out): RDA 1,000, QDA 0,994, LDA 0,989,
1NN 0,961.

**Простым языком:**
Прежде чем доверять весам, их проверяют гирей известного веса. Wine — такая «гиря»: набор данных,
на котором все давно знают правильные ответы. Наши модели угадывают сорт вина с точностью 93–98%,
почти как в научных статьях. Значит, модели реализованы правильно, и их выводам о телефонах можно доверять.

## Словарь терминов

| Термин | Простыми словами |
|---|---|
| **Признак** | Одна характеристика телефона: цена, батарея, вес… |
| **Стандартизация** | Перевод признаков в одну шкалу («сколько отклонений от среднего»), чтобы граммы и мегапиксели можно было сравнивать |
| **Вес признака** | Насколько сильно характеристика влияет на сходство телефонов |
| **Кластер (группа)** | Телефоны с похожим «характером», найденные программой без подсказок человека |
| **Шпиль** | Ценовой класс (бюджет / средний / флагман), внутри которого ищутся группы |
| **k-means (KMeans)** | Алгоритм, который раскладывает точки на k групп вокруг k центров |
| **Силуэт** | Насколько телефон «свой» в своей группе: от −1 до 1 |
| **ARI** | Насколько совпадают два разбиения: 1 — полностью, 0 — как случайные |
| **PCA** | Способ «сплющить» 18 характеристик в 2 оси, чтобы нарисовать карту |
| **Класс / метка** | Категория телефона: 0 — бюджетный, 1 — средний, 2 — флагман |
| **Классификатор** | Модель, которая по входу (анкете) называет класс |
| **Нейросеть (MLP)** | Классификатор из слоёв «нейронов», каждый слой преобразует данные для следующего |
| **Эпоха** | Один полный проход нейросети по всем обучающим примерам |
| **Кросс-валидация** | Данные делятся на 5 частей, модель 5 раз учится на 4 частях и проверяется на пятой — честная оценка |
| **Accuracy** | Доля правильных ответов |
| **F1** | Средняя точность с учётом и пропусков, и ложных срабатываний |
| **Матрица ошибок** | Таблица «что было на самом деле × что сказала модель» |
| **ROC-кривая / ROC-AUC** | Насколько хорошо модель отличает классы; AUC 1 — идеально, 0,5 — монетка |
| **Ансамбль** | Несколько моделей голосуют вместе: Majority Vote, Bagging, AdaBoost |
| **Регрессия** | Модель, которая предсказывает число (например, цену), а не категорию |
| **MAE** | Средняя ошибка прогноза в рублях или процентах |
| **Остаток** | Факт минус прогноз: выше нуля — переплата |
| **Временной ряд** | Значения во времени (цены по дням) |
| **Индекс цен** | Цена относительно «обычной»: 1,05 — на 5% дороже обычного |
| **Дендрограмма** | Дерево последовательного объединения похожих объектов |
| **Взаимная информация (MI)** | Насколько знание признака помогает угадать класс |
