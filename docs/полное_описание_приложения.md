## 1. Что это за программа

Настольное приложение для Windows, которое помогает выбрать смартфон. Человек отвечает на несколько вопросов
(бюджет, для чего телефон, что важнее — камера или батарея), а программа показывает подходящие модели и
объясняет, почему именно они.

Внутри — настоящее машинное обучение, а не просто фильтр «цена до 30 000»:

| Что | Зачем |
|---|---|
| **Классы телефонов** 0 / 1 / 2 | Делим рынок на бюджетный, средний и флагманский сегменты |
| **Кластеризация** (KMeans) | Сама находит группы телефонов «по характеру»: камерофоны, автономные, игровые… |
| **Нейросеть** (MLP) | По ответам угадывает, какой класс телефона нужен человеку |
| **Ансамбли** (голосование, бэггинг, бустинг) | Для сравнения: какая модель угадывает лучше |
| **Ранжирование** | Сортирует телефоны по тому, насколько они подходят именно вам |
| **Поиск похожих** | Ближайшие соседи по характеристикам |

**Технологии:** Python 3.13, PySide6 (окна), SQLite (база), pandas и numpy (таблицы и математика),
scikit-learn (ML), SciPy (иерархическая кластеризация), matplotlib (графики), requests (интернет),
PyInstaller (сборка в один exe).

## 3. Данные: откуда берутся и как хранятся

### 3.1. Откуда
Три источника сливаются в один файл `data/phones_seed.csv`:

| Источник | Что даёт |
|---|---|
| База августа 2026 (`data/sources/base_aug2026.csv`) | 211 моделей с характеристиками и оценками цен. Все остаются в базе |
| Telegram **t.me/ishopper** | Цены из постов со скидками AliExpress и маркетплейсов, характеристики новинок |
| Telegram **t.me/polzaSKIDKI** | Ещё цены и новые модели |

Всего из каналов собрано **≈5 180 цен с датами** (18.07–05.11.2026).

**Правило цены** (`tools/merge_sources.py`):
1. если есть цены за последние 60 дней — берём **медиану** (среднее «по середине», не боится выбросов);
2. иначе — последнюю известную цену из каналов;
3. иначе — августовская оценка.

Перед медианой выкидываются «странные» цены: меньше 55% или больше 180% от общей медианы модели (обычно это
другая память или опечатка). Источник цены пишется в поле `price_source`.

Итог: **287 моделей**, у 115 цены из Telegram, у 172 — августовская оценка. Huawei, Sony и Meizu исключены.

### 3.2. Какие поля есть у телефона

| Поле | Что это | Пример |
|---|---|---|
| `brand`, `model`, `os`, `year` | бренд, модель, система, год | Xiaomi, Xiaomi 17T, Android, 2026 |
| `price_rub` | цена, ₽ | 33 900 |
| `ram_gb`, `rom_gb` | оперативная и постоянная память, ГБ | 12, 256 |
| `battery_mah` | ёмкость батареи, мА·ч | 6 500 |
| `screen_in`, `refresh_hz` | диагональ, частота экрана | 6.59, 120 |
| `weight_g` | вес, г | 195 |
| `camera_mp` | основная камера, МП | 50 |
| `antutu_k` | мощность, тысячи баллов AnTuTu | 2 000 |
| `charge_w` | мощность зарядки, Вт | 67 |
| `has_5g`, `nfc`, `esim`, `ir_port` | есть ли 5G, NFC, eSIM, ИК-порт (1/0) | 1, 1, 1, 1 |
| `active_h` | **расчётные** часы активной работы | 14.3 |
| `standby_d` | **расчётные** дни в режиме ожидания | 21.0 |
| `price_source` | откуда цена | «Telegram (…): медиана 44 цен…» |

### 3.3. Как считается автономность
Реальных замеров у нас нет, поэтому это **оценочная формула** (`src/db.py`, функция `estimate_autonomy`):

```python
eff       = 1 - 0.04 * clip(year - 2023, 0, 3)        # новые чипы экономнее: до −12%
foldable  = screen_in > 7.5                             # книжки тратят больше
active_mA = (380 + 55*(screen_in - 6.0) + 0.35*(refresh_hz - 60)
             + 0.04*antutu_k + 120*foldable) * eff      # ток при включённом экране
idle_mA   = (9 + 3*has_5g + 0.002*antutu_k) * eff        # ток в ожидании

active_h  = battery_mah / active_mA                      # часы активной работы
standby_d = battery_mah / idle_mA / 24                   # дни ожидания
```

**По-простому:** больше батарея — дольше живёт. Больше экран, выше частота, мощнее чип — быстрее садится.
Новые модели чуть экономнее.

Пример: realme P4 Power (10 001 мА·ч) → ≈23 ч активно и ≈34 дня ожидания.

### 3.4. База данных (SQLite)
Файл `phones.db`. При запуске из исходников он лежит в `data/`, у exe — в `PhonePicker_data/data/` рядом с
exe.

| Таблица | Что хранит |
|---|---|
| `phones` | все телефоны |
| `survey_answers` | каждая пройденная анкета (JSON) и предсказанный класс |
| `feedback` | отзывы «Подходит / Не подходит» |
| `price_history` | изменения цен через API |
| `meta` | служебное: хэш датасета |

**Автосинхронизация.** При каждом запуске программа сравнивает хэш (цифровой «отпечаток») файла
`phones_seed.csv` с сохранённым. Если файл поменялся — база сама обновляется: новые модели добавляются,
удалённые убираются (кроме тех, что вы импортировали из своего CSV).

**Проверка данных** при загрузке — функции из курса: `check_data_quality` (пропуски, типы, мусор),
`drop_invalid` (убрать битые строки), `handle_missing` (заполнить пропуски средним).

| Настройка | Варианты | Режим |

**Ползунки важности 0…10** (в простом режиме — первые четыре со звёздочкой):

| Ползунок | Что усиливает |
|---|---|
| Камера ★ | мегапиксели основной камеры |
| Без розетки при активном использовании ★ | `active_h`, немного батарея и зарядка |
| Долго держит заряд в ожидании | `standby_d`, немного батарея |
| Производительность ★ | AnTuTu, ОЗУ, частота экрана |
| Компактность и лёгкость ★ | меньше вес и диагональ |
| Быстрая зарядка | мощность зарядки |
| Много памяти | ОЗУ и постоянная память |
| Новинка, свежая модель | год выпуска |
| Выгодная цена | сильнее «тянет» к дешёвым внутри бюджета |

### 4.2. Результат
- **Простой режим:** топ-5 карточек. В каждой — картинка, цена, класс и группа, характеристики, 3 плюса
  простым языком («≈16 ч активной работы», «камера 200 МП»), кнопки **«Похожие»** и **«Подходит»**.
- **Про-режим:** таблица топ-10 (цена, класс, группа, память, экран, автономность, камера, AnTuTu, eSIM, ИК,

## 5. Как программа оценивает телефоны — по шагам

Общая схема:

```
Опрос → вектор ответов ─┐
                         ├─→ Нейросеть → класс 0/1/2 (с вероятностями) ─┐
Телефоны → признаки → группы (KMeans) ──────────────────────────────────┤
                         └─→ Полезность под ваши ответы ─────────────────┴─→ Итоговая оценка → сортировка
```

### 5.1. Шаг 1. Классы 0 / 1 / 2 («полки» рынка)
Каждый телефон получает класс по взвешенной сумме **рангов** (ранг = какая доля базы хуже: 0 — худший,
1 — лучший):

```python
score = (0.35 * ранг(цена) + 0.25 * ранг(AnTuTu) + 0.10 * ранг(камера)
       + 0.10 * ранг(ОЗУ) + 0.10 * шкала(частота) + 0.05 * ранг(зарядка)
       + 0.05 * ранг(год))
# нижние 40% → 0 «Бюджетный», 40–72% → 1 «Средний», верхние 28% → 2 «Флагман»
```

Почему ранги: у признаков разные единицы (рубли, мегапиксели, баллы), а ранг приводит всё к 0…1.
Частота экрана — не ранг, а линейная шкала **эффективной частоты** (см. 5.2), чтобы 144+ Гц не выглядели
намного лучше 120 Гц.

Сейчас: 115 бюджетных, 91 средний, 81 флагман.

### 5.2. Шаг 2. Признаки и общая шкала (z)
Чтобы сравнивать «яблоки с апельсинами», каждую характеристику переводят в **z-оценку**:

```
z = (значение − среднее по базе) / разброс по базе
```

z = 0 — как у среднего телефона, z = +1 — заметно лучше среднего, z = −1 — заметно хуже.

Две поправки до этого:
- **Логарифм** для цены, ОЗУ, памяти, батареи, AnTuTu, зарядки и веса: `x → ln(1 + x)`. Разница между 4 и
  8 ГБ ощущается сильнее, чем между 16 и 20 ГБ, — логарифм это учитывает.
- **Частота экрана**: до 120 Гц считаем как есть, всё выше — с коэффициентом 0,2:

```python
def effective_refresh(hz):
    return min(hz, 120) + 0.2 * max(hz - 120, 0)
# 60 → 60, 120 → 120, 144 → 124.8, 165 → 129, 185 → 133
```

Камера идёт **без логарифма**: каждый мегапиксель весит одинаково.

Всего 18 признаков: цена, ОЗУ, память, батарея, экран, частота, вес, камера, AnTuTu, зарядка, 5G, NFC,
eSIM, iOS, год, ИК, автономность активно, автономность в ожидании.

### 5.3. Шаг 3. Веса признаков для группировки («чтобы не перетягивали»)
Цена, ОЗУ и AnTuTu почти всегда растут вместе. Если ничего не делать, группировка разделит телефоны просто на
«дешёвые и дорогие». Поэтому у каждого признака свой вес (`src/ml/features.py`):

```python
w = экспертный_вес                                  # камера 0.9, батарея 0.5, цена 1.0, eSIM 0.3…
w = w / (1 + 2 * MI / max(MI))                      # MI — насколько признак «объясняет» класс:
                                                    #   цена и мощность уже в классе → вес меньше
w = w / (1 + 2 * сумма(корреляция − 0.6 при корреляции ≥ 0.6))  # похожие признаки делят вес
w = w / среднее(w)                                   # средний вес = 1
```

MI (mutual information, «взаимная информация») — сколько признак рассказывает о классе.

Результат: силуэт группировки выше (0,27 против 0,20 без весов), группы ближе к «характеру», а не к цене.

### 5.4. Шаг 4. Группы телефонов (KMeans)
KMeans ищет k «центров» так, чтобы телефоны были как можно ближе к своему центру. k выбирается от 4 до 7 по
**силуэту** (насколько телефоны ближе к своей группе, чем к чужой; чем больше, тем лучше).

Название группы — по двум самым выделяющимся признакам центра: например, камера сильно выше средней →
«Камерофоны», есть ИК → «с ИК-портом».

Сейчас 4 группы: «Игровые, быстрая зарядка» (179), «Без 5G, базовые» (44), «Камерофоны, с ИК-портом» (42),
«iPhone, небольшой экран» (22).

### 5.5. Шаг 5. Анкеты для обучения («виртуальные покупатели»)
Настоящих анкет мало, поэтому программа сама генерирует **6 000 виртуальных покупателей** (`labeling.py`):
случайный бюджет (в среднем около 35 000 ₽), случайные ползунки и сценарии (игрок чаще ставит
«производительность» повыше).

Хитрость: у покупателя есть **«скрытые» приоритеты** — те, что в анкете, плюс шум (±1,5 по ползункам,
±8% по бюджету). Так в жизни: человек пишет «камера 7», а на деле выберет по-другому. «Правильный ответ» для
обучения — класс телефона, который лучше всего подходит под скрытые приоритеты:

```python
hidden = анкета + шум
u = utility(hidden, z, phones) + небольшой_шум
правильный_класс = класс_телефона[argmax(u)]
```

Отзывы «Подходит» из базы добавляются к этим анкетам (каждый — 5 раз, это сильный сигнал).

### 5.6. Шаг 6. Нейросеть (MLP)
**Вход:**
- 20 чисел анкеты: бюджет (логарифм), 9 ползунков, 3 сценария, ОС, NFC, eSIM, ИК, размер экрана, частота,
  память (логарифм по основанию 2);
- плюс 2 числа на каждую группу: «лучшая полезность телефона из этой группы для вас» и «доля телефонов группы,
  которые влезают в бюджет».

**Сеть:** 2 скрытых слоя 64 и 32 нейрона, активация ReLU, оптимизатор Adam, регуляризация alpha = 0,001,
ранняя остановка (15% данных на проверку, стоп после 25 эпох без улучшения). Данные делятся
70% / 15% / 15% на обучение, проверку и тест.

**Выход:** вероятности трёх классов, например `[0.05, 0.69, 0.26]` → «Средний, 69%».

Сейчас на тесте: точность 81%, F1 0,79, ROC AUC 0,94.


### 5.7. Шаг 7. Полезность телефона под ваши ответы
Главная формула подбора:

```
Полезность = Σ (вес_признака × z_признака) − Штрафы
```

**Веса из ползунков** (`preference_weights` в `labeling.py`; ползунки делятся на 10, сценарии — 0 или 1):

| Признак | Вес |
|---|---|
| Камера | камера + 0,5 × [Фото] |
| AnTuTu | мощность + 0,8 × [Игры] + 0,2 |
| Частота экрана | 0,4 × мощность + 0,4 × [Игры] + 0,4, если выбрано «от 120 Гц» и выше |
| ОЗУ | 0,4 × мощность + 0,3 × [Работа] + 0,3 × память |
| Память | 0,3 × [Фото] + 0,8 × память + 0,1 |
| Батарея | 0,2 × (активно + ожидание) |
| Автономность активно | активно |
| Автономность в ожидании | ожидание |
| Зарядка | зарядка + 0,2 × активно |
| Диагональ | бонус размера − 0,5 × компактность (бонус: компактный −0,8, большой +0,6, очень большой +0,9) |
| Вес | −0,9 × компактность − 0,2 (тяжёлое всегда чуть минус) |
| Год | 0,1 + 0,8 × новинка |
| 5G, NFC | по 0,2 |
| eSIM | 0,1 × [Работа] + 0,4, если «может быть» |
| ИК-порт | 0,4, если «может быть» |

**Штрафы:**

| Условие | Штраф |
|---|---|
| Дороже бюджета | 30 × (цена/бюджет − 1) — на 10% дороже → −3 |
| «Тяга к дешёвым» (всегда) | (0,3 + 2 × выгода) × цена/бюджет |
| Не та ОС (если выбрана) | −6 |
| Нет NFC (если нужен) | −6 |
| Нет eSIM / ИК при «обязательно» | −6 |
| Не тот размер экрана | −15 × «на сколько дюймов мимо» − 3 |
| Частота ниже выбранной | −5 |
| Память меньше выбранной | −3 |

```python
def utility(a, z, phones):
    u = z @ preference_weights(a)                       # сумма «вес × признак»
    ratio = phones.price_rub / a["budget_rub"]
    u -= 30 * clip(ratio - 1, 0, None)                  # дороже бюджета — резко хуже
    u -= (0.3 + 2 * a["imp_value"] / 10) * ratio        # при прочих равных дешевле лучше
    if a["need_nfc"]:
        u -= 6 * (phones.nfc == 0)
    # … ОС, eSIM, ИК, экран, частота, память
    return u
```

### 5.8. Шаг 8. Итоговая оценка

```
Оценка = нормированная_полезность + 1,5 × P(класс телефона) + 0,4 × [телефон из ближайшей группы]
```

- **Нормированная полезность** — полезность, приведённая к шкале «среднее 0, разброс 1» по всем телефонам.
- **P(класс телефона)** — вероятность, которую нейросеть дала классу этого телефона. Если сеть уверена, что
  вам нужен «средний», все средние телефоны получают ≈ +1,0.
- **Ближайшая группа** — та, где для вас нашёлся самый полезный телефон (берётся из входа нейросети).

```python
# src/ml/recommender.py
u = utility(a, pipe.z_, pipe.phones_)
u_norm = (u - u.mean()) / u.std()
score = u_norm + 1.5 * proba[pipe.labels_] + 0.4 * (pipe.clusters_ == best_cluster)
top10 = argsort(-score)[:10]
```

## 7. Как одно изменение влияет на результат

### 7.1. Камера стала хуже (200 → 50 МП)

```
Δ полезности = вес_камеры × (Δ МП / разброс_камеры)     разброс_камеры = 54,2 МП
Δ оценки     = Δ полезности / разброс_полезности
```

| Анкета | Вес камеры | Δ полезности | Δ оценки |
|---|---|---|---|
| Камера = 5, без «Фото» | 0,5 | 0,5 × (−150 / 54,2) = −1,38 | ≈ −0,10 |
| «Фото и видео» | 1,5 | 1,5 × (−150 / 54,2) = −4,15 | ≈ −0,31 |

Плюс косвенно: в классе у камеры вес 10% (ранг падает с 1,0 до 0,46, то есть ≈ −0,05 к оценке класса),
и телефон может уйти из группы «Камерофоны» и потерять бонус +0,4.

> **Замечание.** Прямой вклад камеры в итог сейчас небольшой. Причина: разброс полезности (≈13–16)
> раздувают огромные штрафы у телефонов далеко за бюджетом, и после нормировки разница между подходящими
> телефонами сжимается. Лечится нормировкой только по подходящим телефонам или по рангам.

## 8. Остальные «умные» функции

### 8.1. «Почему он?»
Для выбранного телефона показывает `вес × z` по каждому признаку: зелёное — плюс, красное — минус. Это те же
числа, что в таблице из раздела 6.

**Плюсы простым языком** для карточек — это 3 самых больших положительных вклада, переведённые в фразы
(«камера 200 МП», «≈16 ч активной работы», «зарядка 100 Вт»).

### 8.2. Похожие телефоны
Ищутся ближайшие соседи — у кого характеристики меньше всего отличаются:

```python
# «по всем параметрам»: расстояние во взвешенном пространстве группировки
dist = ||x - x[телефон]||  − 0.3, если та же группа
# «по камере / автономности / …»: расстояние только по нужным признакам
#   + штраф 10, если цена отличается больше чем на 30%
# «дешевле»: + штраф 100, если цена не ниже 97% исходной
сходство = exp(−dist / медиана_расстояний)          # 100% — одинаковые
```

### 8.3. Отзывы и дообучение
«Подходит» → в таблицу `feedback`. При «Переобучить» каждая такая пара «анкета + телефон» добавляется в
обучение 5 раз с классом этого телефона. Чем больше отзывов, тем ближе модель к живым людям.

## 11. Словарик

| Термин | Простыми словами |
|---|---|
| Признак | одна характеристика телефона (камера, цена…) |
| z-оценка | «на сколько разбросов телефон лучше или хуже среднего» |
| Ранг (перцентиль) | какая доля базы хуже этого телефона: 0,9 — лучше 90% |
| Медиана | значение «посередине» списка; в отличие от среднего, не боится выбросов |
| Кластер / группа | набор похожих телефонов, найденный автоматически |
| KMeans | алгоритм, который делит точки на k групп вокруг k центров |
| Силуэт | оценка качества групп от −1 до 1: чем больше, тем чётче группы |
| PCA | способ «сплющить» 18 характеристик в 2 оси для картинки |
| Нейросеть MLP | несколько слоёв «нейронов», которые учатся переводить ответы в класс |
| Эпоха | один полный проход по обучающим данным |
| Ранняя остановка | прекращаем обучение, когда на проверке перестало становиться лучше |
| Точность (accuracy) | доля правильных ответов |
| F1 | баланс между «не пропустить» и «не ошибиться», среднее по классам |
| ROC AUC | насколько хорошо модель отличает классы (1 — идеально, 0,5 — монетка) |
| Кросс-валидация | обучаем на части, проверяем на остальном, повторяем 5 раз |
| Ансамбль | несколько моделей голосуют вместе |
| Бэггинг | много деревьев на случайных подвыборках, ответ — по большинству |
| AdaBoost | деревья учатся по очереди, каждое исправляет ошибки предыдущих |
| Mutual information | сколько признак рассказывает о классе |
| Полезность | насколько телефон подходит именно вам (до нормировки) |
| Синтетические анкеты | сгенерированные программой «виртуальные покупатели» для обучения |

## 12. Честные ограничения

- **Цены.** У 172 из 287 моделей — августовская оценка, у остальных — медиана скидочных постов без пошлины.
  Реальная цена с пошлиной может быть выше.
- **Характеристики.** Часть новинок заполнена по постам и обзорам, часть — оценками. AnTuTu оценён по
  процессору, ИК-порт — по линейкам.
- **Автономность** — формула, а не замер.
- **Обучение** — на синтетических анкетах; настоящих отзывов пока мало.
- **Выдача однообразна:** 62% телефонов в одной группе, в топ-10 обычно одна группа. Нужна новая система
  отображения (задача в ТЗ функционала).
- **Нормировка полезности** сжимает различия между подходящими телефонами (см. 7.1).
- **iPhone** в базе есть, но без свежих цен из каналов (там их не публиковали).

## 13. Частые вопросы

**Почему мне советуют телефон дороже бюджета?**
Штраф за превышение мягкий: +5% к бюджету — это всего −1,5 к полезности. Если телефон сильно лучше
остальных, он может остаться в топе. В таблице это видно в колонке «Почему» («дороже бюджета на …»).

**Почему 165 Гц почти не дают плюса?**
Выше 120 Гц каждый герц считается с коэффициентом 0,2 — на практике разница почти незаметна.

**Нейросеть выбирает телефон?**
Нет. Она угадывает **класс** (бюджетный / средний / флагман), который вам нужен. Конкретные телефоны
сортирует формула полезности, а класс от сети даёт бонус.

**Почему в простом режиме меньше ползунков?**
Чтобы новичок не путался. Остальные ползунки стоят по умолчанию (или по пресету) и всё равно участвуют в
подборе.

**Как сделать подбор точнее?**
Нажимать «Подходит» у понравившихся телефонов и потом «Переобучить» в аналитике.

**Можно добавить свои телефоны?**
Да: «Данные и API» → «Импортировать из CSV» (те же колонки, что в `phones_seed.csv`), затем «Переобучить».
