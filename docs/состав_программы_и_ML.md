## 1. Коротко

Настольная программа для Windows (Python + PySide6) помогает выбрать смартфон. Пользователь отвечает
на опрос: бюджет, система, требования, 10 ползунков «что важнее». Программа:
1. определяет нейросетью, какой **класс** телефона ему нужен (бюджетный / средний / флагман);
2. оценивает **полезность** каждого из 286 телефонов под его ответы;
3. учитывает **группу** (кластер), к которой тяготеет запрос;
4. выдаёт ранжированный список с объяснением «почему этот», оценкой справедливой цены и советом
   «покупать / ждать».

Отдельная вкладка «Аналитика ML» показывает, как всё это обучено и насколько хорошо работает.

## 4. Данные

### Откуда
1. **База августа 2026** (`data/sources/base_aug2026.csv`) — 211 моделей с характеристиками
   и оценочной ценой маркетплейсов.
2. **Telegram-каналы** t.me/ishopper и t.me/polzaSKIDKI — посты с ценами.
   `tools/scrape_telegram.py` выгружает их, `tools/merge_sources.py`:
   - сопоставляет названия с моделями: длиннейшее совпадение плюс словарь синонимов;
   - добавляет модели, найденные только в каналах;
   - отсекает варианты с другой памятью и опечатки: цена вне 0,55–1,8 медианы;
   - итоговая цена — медиана за последние 60 дней, иначе последняя известная, иначе августовская оценка.
3. Исключены бренды Huawei, Sony, Meizu и лимитированная realme 16 Pro (Harry Potter Edition).

Итог: **286 моделей**, цены из каналов у 114, у остальных 172 — августовская оценка.
История цен — **2036 точек**: у всех моделей есть хотя бы стартовая точка «оценка: август 2026».

### Характеристики (колонки)
бренд, модель, ОС, год, цена, ОЗУ, память, батарея (мА·ч), диагональ, частота экрана, вес, камера (МП),
AnTuTu, мощность зарядки, 5G, NFC, eSIM, ИК-порт, источник цены.

Расчётные колонки:
- **active_h** — часов активной работы: ёмкость / средний ток. Ток растёт с диагональью, частотой
  экрана и мощностью чипа; у складных больше; новые чипы экономичнее, до −12% за 3 года.
- **standby_d** — дней в ожидании: ёмкость / фоновый ток, где 5G и мощный чип тратят больше.

### База SQLite (`data/phones.db`)
| Таблица | Что хранит |
|---|---|
| `phones` | телефоны, флаг архива, расчётная автономность |
| `price_history` | история цен (Telegram, август, обновления через API) |
| `survey_answers` | все пройденные анкеты и предсказанный класс |
| `feedback` | «подходит / не подходит» по телефонам — для дообучения |
| `meta` | хэш датасета: при смене CSV база синхронизируется сама |

Индексы по `phone_id` и дате; миграции колонок через `ALTER TABLE`.

## 5. Все виды ML в программе — сводная таблица

| Вид ML | Задача в программе | Методы | Где в коде |
|---|---|---|---|
| **Предобработка** | привести 18 разных характеристик к одной шкале | логарифм скошенных признаков, обрезка выбросов по p5–p95, стандартизация (свой `StandardScalerCustom`), «эффективная частота» экрана | `features.py` |
| **Отбор и взвешивание признаков** | чтобы цена и мощность не забивали остальное | экспертные веса × делитель по **взаимной информации (MI)** × штраф за **корреляцию** | `features.py` |
| **Понижение размерности** | нарисовать карту телефонов и анкет | **PCA** (2 компоненты) | `features.py`, `experiments.py` |
| **Разметка (rule-based labeling)** | классы телефонов 0/1/2 | взвешенная сумма перцентилей + квантильные пороги | `labeling.phone_labels` |
| **Обучение без учителя: кластеризация** | группы телефонов «по характеру» | **KMeans (k-means++)** внутри каждого класса, k по **силуэту**, стабильность по **ARI**; «броневики» — правилом | `clustering.py`, `classifier._cluster_by_tiers` |
| — для сравнения | проверить, что KMeans — хороший выбор | **агломеративная** (complete, ward), **DBSCAN**, **иерархическая** с дендрограммой, метод локтя, Davies–Bouldin | `clustering.py` |
| **Генерация обучающих данных** | у нас нет тысяч реальных анкет | синтетические анкеты (6000) со «скрытыми» приоритетами и шумом; ответ — класс лучшего телефона | `labeling.generate_dataset` |
| **Обучение с учителем: классификация** | по анкете угадать нужный класс | **нейросеть MLP** (64, 32), ReLU, Adam, ранняя остановка | `ensemble.make_mlp`, `classifier.py` |
| — для сравнения | честно выбрать модель | **логистическая регрессия**, **дерево решений**, **KNN** | `ensemble.model_zoo` |
| **Ансамбли** | повысить надёжность и показать, почему голосование работает | **Majority Vote** (свой класс из лабы), **Bagging**, **AdaBoost** | `ensemble.py` |
| **Дообучение по отзывам** | учесть «подходит / не подходит» | лайк → анкета с меткой телефона ×5; дизлайк → метка лучшего телефона без отвергнутого ×3 | `classifier.fit` |
| **Ранжирование (рекомендательная система)** | упорядочить телефоны под человека | линейная полезность по признакам с весами из анкеты − штрафы + бонус класса + мягкий бонус кластера (softmax) | `recommender.score_phones` |
| **Поиск ближайших соседей** | «Похожие телефоны» | евклидово расстояние во взвешенном пространстве или по группе признаков | `recommender.similar_phones` |
| **Интерпретация** | «Почему этот телефон?» | вклад каждого признака: z-значение × вес из анкеты | `recommender.explain` |
| **Обучение с учителем: регрессия** | «справедливая цена» | **13 методов**: парная, множественная, нелинейная (`curve_fit`), KNN, SVR, дерево, случайный лес, бэггинг, градиентный бустинг, персептрон, MLP; **GridSearchCV**, 5-fold CV | `price_model.py` |
| **Временные ряды** | «покупать сейчас или ждать» | индекс цен по классам; наивный, скользящее среднее, линейная регрессия, случайный лес, бустинг, MLP; горизонты 1 и 7 дней | `price_forecast.py` |
| **Оценка качества** | доказать, что всё работает | accuracy, F1-macro, ROC-AUC, матрица ошибок, силуэт, ARI, NMI, MAE, MSE, корреляция, **NDCG@5** | везде |
| **Абляция** | доказать пользу кластеризации | 7 моделей «с признаками кластеров / без», 5-fold CV | `experiments.ablation` |
| **Эталонная проверка** | проверить реализацию на известных данных | UCI Wine, сравнение с опубликованными результатами | `benchmark.py` |
| **Многокритериальное решение** | веса критериев из попарных сравнений | **AHP** (метод анализа иерархий) с индексом согласованности | `ahp.py` (модуль, в UI пока не выведен) |

## 7. Подробно о каждом ML-блоке

### 7.1 Признаки (`features.py`)
18 признаков:
- непрерывные: цена, ОЗУ, память, батарея, экран, частота, вес, камера, AnTuTu, зарядка, год,
  active_h, standby_d;
- флаги 0/1: 5G, NFC, eSIM, iOS, ИК-порт.

Обработка:
1. **Логарифм** (`log1p`) для скошенных: цена, ОЗУ, память, батарея, AnTuTu, зарядка, вес, камера.
   Разница 4 → 8 ГБ ощущается сильнее, чем 16 → 20.
2. **Эффективная частота экрана**: `min(hz, 120) + 0,2·max(hz − 120, 0)`, потому что 144–185 Гц
   почти не лучше 120 Гц.
3. **Обрезка выбросов** по 5-му и 95-му перцентилям, флаги 0/1 не трогаются. Один телефон-«кирпич»
   на 15 000 мА·ч иначе сжал бы шкалу батареи у всех.
4. **Стандартизация**: среднее 0, отклонение 1. Свой класс `StandardScalerCustom` из лабораторных.
5. **Веса**: экспертный вес × `1 / (1 + 2·MI/MI_max)` / `(1 + 2·избыток корреляции > 0,6)`,
   затем нормировка к среднему 1. Пространство кластеризации — `z · √вес`.

### 7.2 Метки классов (`labeling.phone_labels`)
`score = 0,35·ранг(цена) + 0,25·ранг(AnTuTu) + 0,10·ранг(камера) + 0,10·ранг(ОЗУ)
+ 0,10·шкала(эфф. частота) + 0,05·ранг(зарядка) + 0,05·ранг(год)`.
Пороги — квантили 0,40 и 0,72. Сейчас 114 бюджетных, 92 средних, 80 флагманов.

### 7.3 Кластеризация (`clustering.py`, `classifier._cluster_by_tiers`)
- Телефоны тяжелее 300 г — отдельная группа «Защищённые „броневики“» (4 модели). Их задаёт правило,
  KMeans их не находил.
- Внутри каждого класса («шпиля») отдельный **KMeans k-means++** (`n_init = 20`). k выбирается
  из 3–5 по силуэту: наибольшее k с силуэтом не хуже лучшего более чем на 0,04 и группами
  не меньше 8 моделей.
- Названия групп генерируются автоматически: по двум самым выраженным отличиям центра группы
  от среднего телефона своего класса. Например, «Бюджет · Долго работают, автономные».
- Итог: 5 + 5 + 3 + 1 = **14 групп**.

Почему по шпилям: KMeans на всём рынке склеивал 62% моделей в одну группу («просто дорогие / дешёвые»).

### 7.4 Синтетические анкеты (`labeling.random_survey`, `target_label`)
Реальных анкет мало, поэтому генерируются 6000 правдоподобных:
- бюджет — логнормальное распределение вокруг 35 тыс.;
- важности — нормальное распределение, со сдвигом для геймеров и фотографов;
- требования — с реалистичными вероятностями.

«Правильный ответ» — класс телефона с максимальной полезностью. Полезность считается по **скрытым**
приоритетам: ответы плюс шум σ = 1,5, бюджет ±8%, шум в полезности. Так модель учится на
«живых» людях, которые не всегда точно знают, чего хотят.

### 7.5 Нейросеть-классификатор (`ensemble.make_mlp`)
- `Pipeline(StandardScaler → MLPClassifier(hidden=(64, 32), relu, adam, alpha = 0,001, early_stopping))`.
- Вход — 49 признаков:
  - 21 из анкеты: бюджет (логарифм), 10 важностей, сценарии, ОС, NFC, eSIM, ИК, экран, Гц,
    память (log2);
  - по 2 на каждую из 14 групп: лучшая полезность в группе и доля моделей группы в бюджете.
- Разбиение 70 / 15 / 15 (train / val / test).

### 7.6 Ансамбли (`ensemble.py`)
- **MajorityVoteClassifier** — свой класс из `ens.py` курса: голосование по меткам или по вероятностям
  с весами. В программе голосуют логистическая регрессия, дерево, KNN и MLP по вероятностям, у MLP двойной вес.
- **Bagging** — 200 деревьев на бутстрэп-выборках.
- **AdaBoost** — 200 деревьев глубины 2, последовательно исправляющих ошибки друг друга.

Используются в «Сравнении моделей», «Ансамблях и ROC» и на эталоне Wine. Основной моделью выбран MLP.

### 7.7 Ранжирование (`recommender.py`, `labeling.utility`)
1. **Веса из анкеты.** Например, вес камеры = важность камеры / 10 + 0,5 за сценарий «Фото».
2. **Полезность**: `z · веса − (0,3 + 2·выгода/10)·цена/бюджет + бонус «броневика» − штрафы`.
3. **Штрафы за требования**:
   - дороже бюджета: 30 × превышение;
   - не та ОС, нет NFC, обязательных eSIM или ИК: по 6;
   - не тот размер экрана: 15 × промах + 3;
   - частота ниже нужной: 5;
   - памяти мало: 3.
4. **Нормировка** по подходящим телефонам, чтобы разница между ними была заметна.
5. **Итог**: `оценка = u_norm + 1,5·P(класс телефона) + мягкий бонус группы`. Бонус группы ≤ 0,4:
   softmax по близости к центрам групп × softmax по «насколько группа подходит анкете».
6. **Разнообразие**: не больше 2 моделей одного бренда в топ-5, минимум 3 группы в топ-10.
7. **Блоки**: лучший; дешевле с тем же характером (−15%); премиум-альтернатива (до +25% к бюджету);
   из другой группы.
8. **Значки**: «выгодно», если цена ниже справедливой на 15% и больше; «переплата», если выше на 20%;
   «цена из канала»; «защищённый».
9. **Подсказка при слабой выдаче**: если подходящих меньше 8, показать, какое требование отсекло
   больше всего моделей. Есть кнопка «Ослабить требование».

### 7.8 Похожие телефоны (`similar_phones`)
Ближайшие соседи по евклидову расстоянию во взвешенном пространстве или только по группе признаков:
камера, автономность, производительность, экран, цена. Есть режимы «всё, но дешевле» и «недооценённые».
Для групп признаков действует ценовой коридор ±30%. Сходство в % считается как `exp(−d / медиана d)`.

### 7.9 Справедливая цена (`price_model.py`)
- Цель — ln(цены).
- Признаки — 15 характеристик плюс бренд one-hot (бренды, у которых ≥ 5 моделей).
- 13 методов, параметрические подбираются через **GridSearchCV**, оценка — **5-fold out-of-fold**.
- Победитель — множественная линейная регрессия: MAE 6 185 ₽ (15,8%).
- Справедливая цена телефона — прогноз модели, которая **не видела** этот телефон при обучении,
  поэтому сравнение честное.
- Дополнительно: дерево глубины 3 для наглядности и список «подозрительных цен».

### 7.10 Прогноз цен (`price_forecast.py`)
- Индекс = цена / медианная цена модели, усреднённый по дням для каждого класса и для всего рынка.
- Обучающие примеры — окно последних значений (лаги) → следующий 1 или 7 дней.
- Сравниваются наивный прогноз, скользящее среднее, линейная регрессия, случайный лес, бустинг, MLP.
- Совет в карточке телефона:
  - «хорошая цена», если текущая на 3% и больше ниже обычной;
  - «можно подождать», если прогноз сегмента −2% и больше;
  - «дороже обычного», если +5%;
  - иначе «обычная».

### 7.11 Проверки качества
- **Абляция**: 7 моделей с признаками групп и без, 5-fold CV.
- **ROC** (micro-average, 3-fold), **области решений** на PCA анкет, **биномиальная ошибка ансамбля**.
- **UCI Wine**: те же модели на эталонных данных против опубликованных результатов.
- **NDCG@5** (`python -m src.ml.evaluation`): совпадение топа с экспертным списком на 10 эталонных
  запросах из `docs/reference_queries.json`.
- **pytest**, 22 проверки: метки, признаки, кластеры, рекомендации, история цен и т. д.

### 7.12 AHP (`ahp.py`)
Метод анализа иерархий (Саати). Попарные сравнения «камера важнее батареи в 3 раза» дают матрицу.
Её собственный вектор — веса критериев, отношение согласованности CR < 0,1 — суждения непротиворечивы.
Веса переводятся в значения ползунков 0–10. Модуль готов, в интерфейс пока не выведен:
идея для Ильи — кнопка «Помочь с ползунками».

## 10. Хранение, сборка, тесты

- **Где лежат данные.**
  - Из исходников — в папке проекта: `data/phones.db`, `models/`.
  - Из exe — в папке `PhonePicker_data` рядом с exe. Если писать туда нельзя —
    в `%LOCALAPPDATA%\PhonePicker`.
  - Новая сборка exe сама заменяет устаревшие модели. База с анкетами и отзывами сохраняется.
- **Настройки** (режим, избранное, сохранённые анкеты) хранятся в реестре:
  `HKCU\Software\PhonePicker\PhonePicker`.
- **Сборка**: команда ниже. Она проверяет зависимости, обучает конвейер и модель цены, считает
  эксперименты и собирает `dist/PhonePicker.exe`.
  ```bash
  python build_exe.py
  ```
- **Обновить цены из Telegram**: две команды по очереди.
  ```bash
  python tools/scrape_telegram.py
  ```
  ```bash
  python tools/merge_sources.py
  ```
- **Тесты**:
  ```bash
  python -m pytest -q
  ```

## 11. Известные ограничения

Подробности и исправления — в [аудит_и_тестирование.md](аудит_и_тестирование.md).
1. **Требования мягкие.** Система, NFC, eSIM — штрафы, а не фильтр. При «iOS» в выдаче оказывается Android.
2. **iPhone недооценивается.** Оценка опирается на «цифры из характеристик»: мегапиксели, мА·ч, ватты.
   Автономность — формула без поправки на экономичность iOS. Лучший iPhone — на 144–151-м месте.
3. **Нет вилки цены.** Бюджет — только потолок.
4. **Автономность — оценка, а не замер.** Формула по ёмкости, экрану и чипу.
5. **Анкеты синтетические.** Нейросеть училась на сгенерированных людях. Реальные отзывы
   («подходит / не подходит») постепенно это исправляют.
6. **Цены** у 172 моделей — августовская оценка: в Telegram-каналах они не встречались.
   API магазинов продавцовые и обновляют только товары своего кабинета.
7. **Классы** считаются по характеристикам, а не по цене, поэтому «флагман» может стоить 48 тыс.,
   а «средний» — 95 тыс.
